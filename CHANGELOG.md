# История версий

## 1.0.0 — 2026-09-18

Первый публичный релиз.

- **Портативный exe** (MP4-to-MP3.exe): один файл без установки,
  Python не нужен; ffmpeg, настройки и лог — рядом с exe, следов в
  системе не остаётся. ffmpeg ставится кнопкой «Установить ffmpeg».
- **Окно в фирменном стиле** «бумага и правка»: список файлов,
  настройки-пилюли, живой прогресс с процентами и оценкой остатка
  времени, кнопка остановки, окно «О программе» с лицензиями.
- **CLI**: партии файлов, битрейт, фрагмент, выбор дорожки,
  параллельность, отчёты.
- **Предпросмотр видео** в окне программы: проигрывание, перемотка
  по таймлинии и разметка фрагмента кнопками «Начало здесь» /
  «Конец здесь» (без звука; со звуком — системный плеер).
- **Обработка звука**: нормализация громкости (EBU R128, двухпроходный
  loudnorm), моно для речи, шумоподавление, разбивка на дорожки по
  паузам или по времени с защитой от потери коротких фрагментов.
- **MCP-сервер** для управления из ИИ-агентов (stdio): convert,
  job_status с живым прогрессом, job_stop, check/install_ffmpeg,
  find_videos, probe_media.
- Автоскачивание ffmpeg (gyan.dev/BtbN), сиротских процессов не
  остаётся (Windows Job Object), 124 автотеста + аудиты макета,
  палитры и MCP-диалога.

Ниже — внутренняя история разработки до публичного релиза.

## (внутр.) 1.9.0 — 2026-09-17

Управление конвертером из ИИ-агентов через MCP (Model Context Protocol):

- Новый MCP-сервер (`python mcp_server.py`, `python -m converter.mcp`
  или команда `mp4-to-mp3-mcp` после `pip install ".[mcp]"`).
  Инструменты: check_ffmpeg, install_ffmpeg, find_videos, probe_media,
  convert, job_status, job_stop, jobs_list.
- Конвертация — фоновое задание с живым прогрессом: агент запускает
  convert, опрашивает job_status (проценты внутри файла, overall,
  eta_sec — оценка остатка, результаты по файлам) и может остановить
  через job_stop. Доступны все опции ядра: битрейт, нормализация,
  моно, шумоподавление, фрагмент, разбивка по паузам/времени.
- `converter/jobs.py` — менеджер заданий (только stdlib, отдельно от
  MCP): переиспользуется тестами и может обслуживать другие фронты.
- Ядро и GUI не изменились; зависимость `mcp` — опциональная.
- Живой смоук клиент↔сервер по stdio: scripts/mcp_smoke.py; тесты
  менеджера заданий — tests/test_jobs.py.

## 1.8.1 — 2026-09-17

- Пилюли перерисованы с настоящим сглаживанием. У tkinter Canvas
  нет антиалиасинга: полукруглые концы выходили ступеньками, а
  контурные пилюли собирались из дуг и отрезков со швами на стыках.
  Теперь пилюля (заливка, контур, капы) строится попиксельно с
  аналитическим сглаживанием границы — чистой стандартной
  библиотекой, с кэшем готовых изображений.

## 1.8.0 — 2026-09-17

Портативность и явная установка зависимостей:

- exe не оставляет следов в системе: скачанный ffmpeg, настройки
  окна и лог пишутся в папку рядом с exe (bin\, gui-settings.json,
  mp4tomp3.log). Запасной путь — профиль пользователя — используется
  только если рядом с exe писать нельзя (Program Files, диск только
  для чтения). Настройки из старых версий переносятся автоматически.
- ffmpeg больше не скачивается молча при старте. Программа только
  проверяет его наличие; если его нет — появляется кнопка
  «Установить ffmpeg». Скачивание идёт с прогрессом в зелёной полосе
  («Скачиваю ffmpeg… 42% (34 из 80 МБ)»).
- «О программе» дополнилось: программа портативная, для удаления
  достаточно удалить папку.

## 1.7.0 — 2026-09-17

Живой отклик во время конвертации — раньше полоса двигалась только
между файлами, и было непонятно, что происходит и сколько ждать:

- Статусная строка показывает текущий файл, номер из общего числа
  («2/5»), проценты внутри файла и оценку оставшегося времени
  («осталось ~4:05»); при включённой нормализации — этап замера
  громкости.
- Зелёная полоса прогресса двигается внутри файла (парсинг
  `-progress` ffmpeg передан из ядра через новый колбэк
  `on_progress(index, name, fraction)`), а не скачками по файлам.
- Оценка времени появляется после 2% прогресса — раньше первых
  процентов оценка слишком врёт.
- Итоговое окно показывает время работы в читаемом виде («за 2:31»).
- При разбивке на дорожки прогресс течёт по дорожкам внутри файла.
- `converter.util.human_time` (секунды → «М:СС»/«Ч:ММ:СС») + тесты;
  дизайн-аудит проверяет, что прогресс шевелится внутри файла и
  статус показывает проценты/время.

## 1.5.1 — 2026-09-16

Полировка дизайна по итогам визуального аудита (кадры окна сняты
PrintWindow и сверены с дизайн-системой «бумага и правка»):

- Курсор знака «−mp4 +mp3▮» приведён к спецификации марки:
  0,28×0,9 em с опусканием к базовой линии и зазором от «+mp3» —
  раньше был крупнее текста и слипался с ним.
- Выделение строки в списке файлов почти не отличалось от белой
  карточки — заменено с бледной подложки на цвет «линия».
- Обводка чекбоксов на экранах с масштабированием была тоньше
  чернильного веса текста (1 физический пиксель) — теперь масштабируется.
- Поле ввода при фокусе подсвечивается зелёным (фокус по дизайн-системе).
- В ряду действий осталась одна залитая кнопка («Добавить видео…»),
  «Добавить папку…» переведена в контурную — главная кнопка экрана
  теперь одна, «Конвертировать».
- Единственный цвет мимо токенов (#B9BBC1 в подзаголовке шапки)
  заменён на фирменный ON_DARK_MUTED.
- Новый аудит: scripts/design_audit.py — снимает окно во всех
  состояниях и проверяет палитру кадра по токенам (посторонние
  доминирующие цвета = признак «системного» виджета).

## 1.5.0 — 2026-09-16

Охота за багами (логика + графика), найдено и починено:

- Фрагмент (--start/--end) за пределами длинного файла помечался
  «успехом» и оставлял пустой mp3 ~700 байт. Теперь файл удаляется,
  а в отчёте понятная причина: «ничего не записано — фрагмент за
  пределами файла или звук короче секунды».
- API принимал пути-строки, но падал с TypeError на dst_dir-строке
  (проявлялось как «внутренняя ошибка» в партии). Пути нормализуются
  в Path в convert_file/split_to_tracks/convert_batch, а любой сбой
  воркера партии превращается в честный FAILED-результат вместо
  падения всей очереди.
- Сиротский ffmpeg: если процесс конвертера убивают, кодек-процессы
  теперь умирают вместе с ним (Windows Job Object,
  KILL_ON_JOB_CLOSE). Раньше могли остаться висеть и держать файлы.
- Гонка в GUI: фоновый поток читал tk-переменные чекбоксов напрямую —
  при редком стечении «main thread is not in main loop» и срыв
  конвертации. Значения снимаются снапшотом в главном потоке до
  запуска воркера.
- Минимальный размер окна: контент мог вылезать за правый/нижний край
  (пилюли битрейта, кнопки). minsize теперь вычисляется по фактической
  требуемой ширине/высоте макета, а не по константе.

## 1.4.1 — 2026-09-15

- Чёткость на экранах с масштабированием: процесс теперь
  DPI-информированный (SetProcessDpiAwareness), окно рендерится в
  нативных пикселях вместо растяжения битмапой Windows. Все шрифты,
  высоты кнопок и отступы масштабируются на коэффициент экрана
  (у 150% — ×1.5). До этого на high-DPI буквы были рваными, скругления —
  ступенчатыми.

## 1.2.1 — 2026-09-14

- Разбивка: короткие куски больше не выбрасываются, а подклеиваются
  к соседним дорожкам (включая первый кусок) — содержание не теряется,
  покрытие по времени 100%. Найдено циклом проверок на реальной записи.
- CLI: новый флаг `--silence-min` — минимальная длина паузы
  (для речи 0.5–0.8 с).
- `scripts/realdata_cycle.py` — цикл проверок на реальном видео
  (10 сценариев: конвертация, фрагмент, нормализация, речь, разбивки,
  ошибки, отмена).

## 1.2.0 — 2026-09-14

- Разбивка на дорожки: по паузам (`--split-silence`, рез по серединам пауз;
  настраиваются порог `--silence-db` и минимальная длина `--min-track`)
  и по интервалу (`--split-every 10:00`). В окне — выпадающий список «Разбивка».
- Нормализация стала двухпроходной: сначала замер громкости, затем линейная
  подстройка (loudnorm linear=true, EBU R128 −16 LUFS) — без компрессии,
  по схеме эталонного ffmpeg-normalize.
- Шумоподавление для речи: `--denoise` (highpass 80 Гц + afftdn).
- Выбор звуковой дорожки в многодорожечном видео: `--audio-stream N`.
- Тестов стало 94 (было 61).
